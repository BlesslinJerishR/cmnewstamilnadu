# 11. DEDUPLICATION SYSTEM

This is a critical component.

GDELT searches will overlap.

The same article may appear:

* in multiple searches
* multiple times across ingestion windows
* with URL variations
* with tracking parameters
* with slightly different metadata

Design a multi-layer deduplication strategy.

Recommended levels:

1. Canonical URL
2. Normalized URL
3. Content/title hash
4. Source + normalized title + publication time
5. Similarity detection for near-duplicate articles

The initial near-duplicate strategy must remain lightweight.

Do NOT use AI embeddings.

Do NOT use vector databases.

Do NOT use LLMs.

Use deterministic text normalization and OpenSearch/PostgreSQL capabilities where appropriate.

Explain which method should be the primary unique identifier.

Explain how PostgreSQL should enforce uniqueness.

Also explain how to identify syndicated articles where multiple publishers publish substantially the same story.

# FINAL PRINCIPLE

Implement this as a **small, reliable platform integration**, not as a large feature.

Google Play owns the update distribution.

Our application owns the user experience around it.

The update mechanism should be:

Reliable

Non blocking

Secure

Minimal

Native feeling

Resource efficient

Easy to maintain

Compatible with the existing application
